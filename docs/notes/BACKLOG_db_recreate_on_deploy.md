# Бэклог: деплой может пересоздавать `nexus-arcana-db`

Статус: наблюдение 2026-11-16, не исправлено. `scripts/deploy.sh` не менялся (серверный `~/deploy.sh`
идентичен, ADR-0014).

## Суть

`deploy.sh` на КАЖДОМ деплое собирает образ БД (`docker buildx build … docker/postgres -t nexus-arcana-db:latest`),
затем `docker compose up -d`. Если образ получил новый ID, compose пересоздаёт контейнер БД, даже когда
`docker/postgres/` не менялась (последний раз 2026-06-25). В `docker/postgres/Dockerfile` есть
`apt-get update && apt-get install postgresql-16-pgvector` без закреплённых версий, поэтому ID образа зависит
от кэша сборки и от того, какой слой «postgres:16» лежит на сервере.

Наблюдение: деплой 14.11 (`087b7f8`) оставил БД `Running`; деплой 16.11 (`7ac9d1d`) пересоздал её
(образ создан 11:15:51Z, `Recreate` 11:17:50Z). Почему кэш не сработал, не выяснено.

## Цена

- Простой БД около 12 с (`Recreate` → `Healthy`), при этом боты ещё старые и держат соединения.
- Данные целы: остановка штатная (`shut down at …`, без crash recovery), том `nexus-arcana_pgdata` тот же.
  Перед пересозданием `deploy.sh` делает проверенный `pg_dump` (`predeploy_*.dump`).
- Риск небольшой, но он плавающий: тот же класс события, что любой рестарт Postgres посреди запросов ботов.

## Два варианта лечения

1. **Пересобирать образ БД только при изменении `docker/postgres/`.** В `deploy.sh` перед `buildx build` для БД
   сравнить `git diff --name-only <старый HEAD>..HEAD -- docker/postgres` (или хеш содержимого каталога с меткой
   образа) и пропускать сборку, если не менялось. Можно дополнительно закрепить версию `postgresql-16-pgvector` и
   digest базового образа. Плюс: образ БД обновляется осознанно. Минус: правка серверного `deploy.sh`.
2. **Не пересоздавать БД при `up -d`.** Поднимать только ботов: `docker compose up -d nexus arcana zarya`
   (с `--no-deps`, если не нужна проверка зависимостей) или `--no-recreate` для БД. Плюс: БД никогда не
   перезапускается деплоем. Минус: реальное изменение образа БД придётся применять вручную отдельным шагом.

Рекомендация: вариант 1 (с закреплением версий), он не скрывает настоящие обновления образа.
