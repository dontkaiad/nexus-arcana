# Списки и инвентарь «для ситтера» (GET /api/sitter/lists)

Узкое служебное чтение для приложения-ситтера (heylark_cats): только пункты списков с пометкой `for_sitter`, по отдельному токену.
Без доступа к Памяти, остальным спискам, задачам, финансам.

## Что видит ситтер (одно условие)
`core/repos/pg_sitter_lists_repo.sitter_visible_clause` — единственное место, где записано правило (его используют чтение ситтера,
предпросмотр владельца и поиск ситтера):

    user_id = владелец AND status != 'archived' AND (
        (list_type = 'инвентарь' AND NOT sitter_hidden)               # инвентарь открыт по умолчанию
        OR (list_type IN ('покупки','чеклист') AND for_sitter) )      # покупки и чеклисты только по пометке

- `nexus_lists.for_sitter` (миграция `f7d0b3e5c942`, default false) — только для покупок и чеклистов; на инвентаре игнорируется.
- `nexus_lists.sitter_hidden` (миграция `b9f2d6a1c850`, default false) — только для инвентаря; на покупках и чеклистах игнорируется.
- `nexus_lists.location` (миграция `f4a8c2d6e913`, NULL = не указано) — где лежит пункт инвентаря; отдаётся ситтеру полем `location` (в `inventory` и в ответе `/api/sitter/ask`), правится в карточке пункта Mini App (только Nexus-инвентарь).
- Новый пункт инвентаря виден сразу (без записи флагов), новая покупка или чеклист нет, пока владелец не пометит.
- Не путать с `shared` («видно Заре»).

Владелец (обычный вход): `POST /api/lists/{id}/sitter` `{for_sitter}` (покупки/чеклист), `POST /api/lists/sitter-group` (весь чеклист),
`POST /api/lists/{id}/sitter-hidden` `{hidden}` (инвентарь; не из инвентаря или чужой пункт → 404),
`GET /api/lists/sitter-preview` — ровно то, что получит ситтер (тем же кодом), плюс `id`. В Mini App: 🐾 и 🙈 в карточке пункта,
🐾 в шапке чеклиста, «👁 Ситтер» в «Списках».

## Чтение
`GET /api/sitter/lists` с `Authorization: Bearer <SITTER_LISTS_TOKEN>`:

    {"lists": [{"name": "<группа>", "items": [{"name","note","quantity","done","kind"}]}], "count": N,
     "inventory": [{"category": "<категория>", "items": [{"name","note","quantity"}]}], "inventory_count": M}

- `lists` — только помеченные покупки и чеклисты (по `group_name`), `inventory` — только видимый инвентарь (по `category`).
  Старые клиенты читают только `lists` и новый ключ игнорируют.
- В ответе нет id, цен, магазина, приоритета, ссылок на задачи/работы. Тексты обрезаются (название 120, заметка 300, группа и
  категория 60), управляющие символы убираются. Экранирование HTML выполняет клиент.
- Ответ: `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `application/json`.

## Доступ
Один читающий токен ситтера `SITTER_LISTS_TOKEN` обслуживает все читающие маршруты для ситтера (`/api/sitter/lists`, `/api/care/schedule`,
`POST /api/sitter/ask`); запись (выполнение цикла, перенос) идёт по ОТДЕЛЬНОМУ токену. Список маршрутов, открытых токеном, зафиксирован тестом.

- Жёсткий Bearer-шлюз `sitter_lists_gate`: нет заголовка / неверный токен → 401, на initData и cookie не «проваливаемся».
- Токен ОТДЕЛЬНЫЙ, не взаимозаменяем: токен котов (`CATS_READ_TOKEN`) сюда не подходит, токен ситтера не открывает ни `/api/cats`,
  ни другие маршруты. Если `SITTER_LISTS_TOKEN` совпал с `CATS_READ_TOKEN`, короче 32 символов, владелец не задан или не входит в
  `ALLOWED_TELEGRAM_IDS` → доступ выключен (401).
- 10 неверных попыток за 60 с с одного IP → 429 (собственное окно, с токеном котов не смешивается). Сравнение `hmac.compare_digest`,
  токен только из окружения, в логи не попадает.

## Окружение
`SITTER_LISTS_TOKEN` (`openssl rand -hex 32`), `SITTER_LISTS_OWNER_TG_ID`. Живут только в `.env` на сервере; в heylark_cats токен
добавляется отдельным шагом деплоя (как у токена котов).

## Откат
`downgrade` миграции удаляет колонку и индекс (пометки теряются, пункты нет). Токен можно отозвать, убрав его из `.env`.

## Паспорта котов: `GET /api/sitter/cat-care`

Тот же читающий токен ситтера и тот же жёсткий гейт (токены котов, записи ухода, периода и здоровья сюда не подходят). Читает и ничего не пишет. Отдаёт:

| Блок | Что именно |
|---|---|
| `cats` | подтверждённые коты: `id`, имя, фото (безопасный https), актуальные факты четырёх типов (`important`, `other`, `likes`, `dislikes`; до 8 / 8 / 6 / 6, до 300 знаков), без кличек и id фактов |
| `meds` | ДЕЙСТВУЮЩИЕ курсы (идут сегодня) без скрытых владельцем (`sitter_hidden`): `cat_id`, название, доза, приёмов в день, `ends_on`, `days_left` |
| `weights` | только взвешивания с флагом `sitter_visible`: `cat_id`, дата, граммы (последние 12 на кота) |
| `visits` | только визиты с флагом `sitter_visible`, запланированные и за последние 60 дней: `cat_id`, вид, название, дата, статус, `days_until` |

Нет: заметок, клиник, следующих сроков, id задач, статусов курса, денег. «Сегодня» и числа дней считает Nexus в часовом поясе владельца. Окно доступа ситтера (даты stay) проверяет приложение cats, Nexus его не знает.
